# Acceptance toolkit

This directory is the repository-only toolkit for the 11 stable VM scenarios. Read the normative [Chinese acceptance manual](../../docs/zh-CN/acceptance.md) and its synchronized [English translation](../../docs/en/acceptance.md) before using it. Never copy this directory into a candidate ZIP, and never write raw evidence into the repository.

## Tools

- `Capture-SystemState.ps1` writes a new schema-v2 JSON file containing the OS build, process/user/machine proxy, WinINET, WinHTTP, WinGet feature, firewall profiles, adapters, and stably ordered IPv4/IPv6 address, route, and DNS observations.
- `Compare-SystemState.ps1` reports top-level state drift and before/after SHA-256 values.
- `Compare-StableStatuses.ps1` exactly compares expected and observed per-application stable statuses.
- `Invoke-ReleaseCandidate.ps1` runs the extracted candidate under Windows PowerShell 5.1 and writes only redacted stdout/stderr plus a hashed command summary.
- `Invoke-SelfElevationProbe.ps1` must start from an ordinary Windows PowerShell. Its default `Exit0` scenario selects and skips Chrome; `-Scenario Exit10` selects the fail-closed RealVNC Viewer entry and requires the candidate to preserve `ManualActionRequired` as exit 10. Each invocation exercises exactly one real UAC handoff without calling an installation provider, and the probe itself exits 0 only when the candidate result matches.
- `Test-ExplicitProxyHttps.ps1` proves an explicit process proxy can complete a real HTTPS request; a listening port alone is not success. VM-006 fixes the probe at `https://www.microsoft.com/favicon.ico` and must pass `-ProxyUri http://192.168.77.1:7897`.
- `Invoke-InstallerTrustProbe.ps1` creates its signed fixture only in `%TEMP%`, invokes the exported production trust boundary for VM-007, records `Executed=false`, and exits 30.
- `Write-EvidenceManifest.ps1` checks a draft against the strict, secret-free contract in `evidence.schema.json` and refuses to overwrite output.
- `gateway/` contains the restricted, no-MITM VM-004/006 Gateway policy generator, CONNECT fault proxy, redacted `capture_gateway_state.py` collector, and tests. VM-004 has independent `chrome` automatic-local-proxy and `bandizip` explicit-local-proxy legs; VM-006A/B always use the explicit remote Gateway proxy.

Every output path must be new and located on the private evidence VHDX. Run the candidate from an expanded, SHA-256-verified, attestation-verified ZIP. Keep the candidate and toolkit commits, workflow URL, archive digest, runtime fingerprint, VM/checkpoint/build identities, command hash, stable statuses, before/after hashes, and relevant file hashes in each manifest.

Gateway network and fault-proxy policies are create-new root-owned private `0600` JSON files under a repository-external path such as `/var/lib/w11b-private/v0.1.0/`; they are not evidence. Record their SHA-256 values and endpoint/rule counts, but never copy their bodies or disclose a Clash subscription, node, or node-to-IP association. Run `capture_gateway_state.py` as root from the frozen root-owned fixture immediately before and after the SUT operation. Every invocation uses the required `--profile`; VM-006 additionally requires `--ready-file`, while VM-004 forbids it and requires no Gateway port-7897 listener. The collector checks the complete lo/WAN/LAN, address, all-table route, IP policy-rule, forwarding, exact nftables, firewall, and listener/process state. Each output is a direct child of a trusted root-owned, non-symlink, non-group/other-writable evidence parent and is created root-owned `0600`; this guest collector does not replace the separate host-side NTFS evidence VHDX attachment/mount gate. Output contains hashes, counts, and redacted identities but no raw policy, WAN address/route, MAC, interface name, or private path. Fault-proxy JSONL contains only timestamp, role, event, and bytes. Capture redacted Gateway counters/events and SUT network state before and after. Every VM-004 profile and each VM-006A/B branch starts by restoring the clean powered-off Gateway checkpoint; after evidence extraction restore that checkpoint again instead of manually deleting nftables tables. During the scenario the SUT connects only to `W11B-Lab`, has no usable global IPv6 address or global/default IPv6 route, and retains exactly equal adapter, IPv4/IPv6 address and route, DNS, and persistent-proxy state before and after.

Automated redaction does not make evidence public. Inspect every file manually before posting a minimal summary to Issue #1. If a credential, subscription, token, password, license, or private identity is found, destroy the evidence and restore the clean checkpoint.
