# Acceptance manual

## Scope and authority

This manual governs v0.1.0 Windows 11 VM acceptance. The maintainer controls Hyper-V, UAC prompts, reboots, private activation, and the one-time Clash subscription entry. The acceptance scripts collect and compare evidence but never manage Hyper-V, activate Windows, enter credentials, reboot, or publish a release. A merged acceptance PR is only a release gate; creating `v0.1.0` still requires a separate explicit instruction.

Keep raw evidence on a repository-external, dynamically expanding NTFS VHDX such as `D:\VM\win11-bootstrap-private\evidence.vhdx`. Do not attach that VHDX to GitHub. Never record accounts, license keys, tokens, passwords, subscription URLs, authorization headers, or private VM screenshots. Destroy and rerun any evidence set in which a secret is found.

## Candidate freeze

1. Merge the acceptance-tooling PR after `validate` and `acceptance-tools` pass.
2. On `main`, manually run the Candidate workflow. Download its ZIP and `.sha256` into a new evidence directory.
3. Verify both controls:

   ```powershell
   (Get-FileHash .\win11-bootstrap-v0.1.0.zip -Algorithm SHA256).Hash
   gh attestation verify .\win11-bootstrap-v0.1.0.zip --repo UnbalancedCat/win11-bootstrap
   ```

4. Expand the ZIP, run `tests/Get-RuntimeFingerprint.ps1` from the matching toolkit checkout with `-RepositoryRoot` set to the expanded directory, and record the candidate commit, workflow URL, archive SHA-256, runtime fingerprint, toolkit commit, and successful attestation result.
5. From an ordinary, non-administrator Windows PowerShell, run `tests\acceptance\Invoke-SelfElevationProbe.ps1 -CandidateRoot <expanded-candidate>` and then repeat it with `-Scenario Exit10`, using the matching toolkit commit. Each invocation must show exactly one UAC prompt and call no installation provider. The first requires the candidate's skipped selection to return 0; the second requires the fail-closed RealVNC Viewer selection to preserve `ManualActionRequired` as 10. Each probe exits 0 only after matching its expected candidate result. Never bypass a failure by starting the candidate as administrator.
6. Then preflight `clash-verge-rev`, `chrome`, `git`, `codex-desktop`, `realvnc-server`, and `nomachine-client`, and repeat the same command once. A runtime or catalog change requires a separate PR, a new candidate, restoration of the clean checkpoint, and a complete preflight rerun. Freeze only after package IDs, Store identity, pinned versions, and manual-only sources are rechecked.

Any functional change to a runtime-whitelisted file or the acceptance toolkit invalidates every formal result. Restore the final golden checkpoint and rerun beginning with VM-011. Complete all formal scenarios within seven natural days and record the OS build for every run.

## Baselines

The Windows SUT is a Generation 2 Windows 11 Pro x64 VM with Secure Boot, vTPM, 4 vCPU, 4/8/12 GB dynamic memory, a 128 GB dynamic VHDX, Hong Kong locale/UTC+8, a local administrator, current Windows Updates, and nested virtualization. The golden checkpoint contains no candidate, toolkit, personal account, or Clash subscription.

VM-004 and VM-006 additionally use the two-NIC Ubuntu Gateway documented under `tests/acceptance/gateway/`: WAN on Default Switch, LAN on private switch `W11B-Lab`, Gateway `192.168.77.1/24`, and SUT `192.168.77.10/24`. During a scenario the SUT must be connected only to `W11B-Lab`; Default Switch, `W11B-Direct`, and every other adapter must be absent. On `W11B-Lab`, the SUT must have no usable global IPv6 address and no global or default IPv6 route; the Gateway must also drop IPv6 arriving from the LAN so that IPv6 cannot bypass the fixture. Before applying each `vm004-bootstrap`, `vm004-subscription`, `vm004-runtime`, or `vm006` profile, restore the same powered-off clean Gateway baseline checkpoint. Restore that checkpoint again after evidence extraction; manually deleting nftables tables is not an accepted cleanup. The fixture performs no TLS interception and changes no persistent host or SUT proxy, certificate, firewall, or WinHTTP setting.

## Evidence commands

Mount a fresh evidence VHDX directory for the scenario. Before and after each run:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\acceptance\Capture-SystemState.ps1 -OutputPath E:\VM-006\before.json
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\acceptance\Invoke-ReleaseCandidate.ps1 -CandidateRoot C:\Candidate -ScenarioId VM-006 -OutputDirectory E:\VM-006\run -BootstrapArguments '-Only','chrome','-Yes','-ProxyUri','http://192.168.77.1:7897'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\acceptance\Capture-SystemState.ps1 -OutputPath E:\VM-006\after.json
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\acceptance\Compare-SystemState.ps1 -BeforePath E:\VM-006\before.json -AfterPath E:\VM-006\after.json -OutputPath E:\VM-006\comparison.json
```

The runner writes redacted stdout/stderr, their hashes, the command-summary hash, timestamps, and exit code. It rejects secret-bearing arguments. `Write-EvidenceManifest.ps1` canonicalizes a completed manifest conforming to `evidence.schema.json` and refuses suspected secrets. Human review remains mandatory before a summary or screenshot is posted to Issue #1.

A Gateway network policy must be a create-new private JSON file owned by the invoking user, not a symlink, and mode `0600`, for example `/var/lib/w11b-private/v0.1.0/VM-004/chrome-vm004-runtime.json` or `/var/lib/w11b-private/v0.1.0/VM-006/a-network.json`. A network policy contains only canonical single public IPv4 addresses with exact protocols and ports; CIDRs, ranges, and implicit targets are forbidden. A VM-006 fault-proxy policy must additionally pin each host to reviewed public IP addresses. A policy is not evidence and must not be copied to the evidence disk, repository, or GitHub. Evidence records only the policy/rules SHA-256 values, blocked/allowed or rule counts, redacted counters, fixture event types, and byte counts; it must not disclose a Clash subscription, nodes, or the association between nodes and IP addresses.

Run `capture_gateway_state.py` as root from the frozen root-owned, non-symlink fixture immediately before and after the SUT operation. Every call supplies the required `--profile`. A VM-004 call uses the matching `vm004-bootstrap`, `vm004-subscription`, or `vm004-runtime`, omits `--ready-file`, and requires no TCP/UDP bind on Gateway port 7897. VM-006 uses `--profile vm006` and also requires `--ready-file`; the one exact `192.168.77.1:7897` TCP listener must be the live root `/usr/bin/python3` process running the frozen fixture with root-owned `0600` policy, log, and ready files bound to the ready profile/hash. The collector admits only the unique lo/WAN/LAN inventory; captures all addresses, all-table IPv4/IPv6 routes, and exact standard IPv4/IPv6 policy rules; requires IPv4 forwarding 1 and both IPv6 forwarding controls 0; and compares the full nftables tables, chains, ordered matches, counters, verdicts, and NAT semantics with the selected policy. Each output is a create-new root-owned `0600` direct child of a root-owned, non-symlink, non-group/other-writable trusted evidence parent. This guest-side gate does not replace host verification that the parent is on the approved private NTFS evidence VHDX. Output records only hashes, counts, redacted network identities, counters, and validated process identity, never the raw policy, raw WAN addresses/routes, raw MACs, interface names, or private paths. Compare both captures and block unexplained identity drift; exact VM-004/VM-006 before/after commands are in `tests/acceptance/gateway/README.md`.

## Formal order and verdicts

Run in this order: VM-011, VM-001 with VM-010, VM-009, VM-002, VM-003, VM-004, VM-005, VM-006, VM-007, VM-008.

- **VM-011:** golden checkpoint, default selection with `-WhatIf -Yes`. Exit 10 is allowed only for planned manual catalog items. There must be no elevation, download, log, registry/feature/proxy change, or other state change.
- **VM-001/010:** default interactive run. Automated items install; Xftp, Xshell, and RealVNC Viewer are manual; WSL needs restart; Store may be manual only with a precise instruction. Exit 10, with no ordinary `Failed`, is expected. Verify every account/portal/license/first-run instruction.
- **VM-009:** after each manual reboot, run `-Only wsl2-ubuntu -Yes` until Ubuntu 24.04 is detected as WSL version 2. The script must not reboot, launch Ubuntu, or create a Linux user.
- **VM-002/003:** preinstall Chrome and Git with WinGet. Run `-Only chrome,git,vscode -Yes`, then repeat it. First verdict: two `AlreadyInstalled`, VS Code `Installed`, exit 0. Second: all `AlreadyInstalled`, exit 0, no installer execution.
- **VM-004:** freeze two isolated Ready-target legs: `chrome` proves automatic discovery of local Clash at `127.0.0.1:7897`, and `bandizip` proves an explicit `-ProxyUri` for that same proxy. Each target leg begins from the same clean Windows gold and clean Gateway checkpoint; one target's state must never become the other's baseline. First configure `vm004-bootstrap` with a create-new private policy that permits only the exact endpoints required to install Clash and blocks the selected target. The first run must install Clash and return `NeedsProxy/10` for the target. Restore the clean Gateway, configure `vm004-subscription`, enter the subscription only in the Clash UI, and keep system proxy and TUN off. Restore the clean Gateway again and configure `vm004-runtime`, permitting only exact frozen node endpoints while continuing to block the target's direct path. The `chrome` run must omit `-ProxyUri` and let the runtime discover `127.0.0.1:7897`; the `bandizip` run must pass `-ProxyUri http://127.0.0.1:7897`; each exits 0 independently. Record Gateway policy/rules hashes, counts, and nftables counters before and after every profile, and prove that the SUT adapters, IPv4/IPv6 addresses and routes, DNS, and persistent proxy state are exactly equal before and after. After evidence extraction, destroy the subscription-bearing SUT branch and restore the clean Gateway checkpoint.
- **VM-005:** from separate clean restores, establish and record one fully absent App Installer state and one supported package-present/current-user-registration-or-command failure. Repair must restore trusted WinGet and install the test package. If the current build cannot safely create the second state using supported AppX operations, release remains blocked; do not replace it with a shim or edited system file.
- **VM-006:** A and B are independent branches; each starts from clean Windows gold and the clean Gateway checkpoint, uses a create-new `vm006` network policy, and runs `chrome` with the explicit remote `-ProxyUri http://192.168.77.1:7897`. The frozen probe is `https://www.microsoft.com/favicon.ico` (host `www.microsoft.com`). A's create-new `vm006a` fault-proxy policy contains only a `reject` rule for that probe and no upstream address: the explicit-proxy probe must fail and the candidate must yield `NeedsProxy/10`. B's create-new `vm006b` policy pins and relays the probe through reviewed public IP addresses, pins and relays at least one frozen metadata host, and pins at least one frozen payload host whose transfer is dropped after 65536 bytes. The explicit-proxy probe must first succeed; the candidate must then lose the installer payload transfer and yield `NeedsProxy/10`. Chrome remains absent in both branches. WinGet feature, WinINET, WinHTTP, environment, firewall, and the SUT adapter, IPv4/IPv6 address and route, and DNS observations are exactly equal before and after. Evidence must include create-new ready metadata, Gateway policy/rules hashes and counts, nftables counters, and either A's rejection event or B's probe/metadata relay and payload-drop events; it must not contain the private policy body. Restore the clean Gateway checkpoint after extraction instead of manually deleting tables.
- **VM-007:** run `Invoke-InstallerTrustProbe.ps1` in the real VM. Its two runtime-created cases call production `Test-InstallerTrust`, return `NonCompliant/30`, and record `Executed=false`. This tests the production trust boundary, not a live-mirror end-to-end path.
- **VM-008:** in an isolated snapshot, create synthetic uninstall entries for RealVNC v8 and legacy NoMachine server/Personal Edition v10, then invoke the real `bootstrap.ps1` with the corresponding protected keys. Both must be `NonCompliant/30`, with no WinGet, uninstall, overwrite, or downgrade invocation. A separate Enterprise Client v10 record must not trigger the legacy server gate. Remove the snapshot after evidence review.

## Public record and retention

Record the candidate and toolkit commits, runtime fingerprint, archive SHA-256, VM UUID/checkpoint, OS/WinGet builds, command hash, exit/statuses, before/after hashes, file hashes, Gateway policy/rules hashes and counts, redacted counters, and fixture events. Post only redacted verdicts and necessary redacted screenshots to Issue #1. Keep valid raw evidence and a secret-free golden checkpoint until 30 days after v0.1.0 is published. Destroy any Clash-bearing branch immediately after evidence extraction.
